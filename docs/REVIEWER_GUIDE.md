# Start here: reviewing CommerceOps AI

CommerceOps AI is a human-supervised commerce operations MVP. It separates deterministic eligibility/calculations, structured model output, human decisions and external effects. The recorded live samples use synthetic records; the project does not claim production commerce experience or measured business improvement.

## A four-minute review

1. Watch the [six-workflow walkthrough](../evidence/reviewer-walkthrough.mp4). The saved fixture examples show all six processors, their output/action boundaries, consent failure and duplicate suppression. The final segment contains the separate verified live service samples.
2. Inspect the [live Shopify verification](../evidence/shopify-live-delivery.md) and [cart task/row readbacks](../evidence/live-cart-demonstration.md). Genuine provider delivery and independently verified remote writes have stronger evidence than configured credentials.
3. Check [failure tests](../tests/test_system.py), [the Engine](../backend/engine.py) and [actual n8n exports](../workflows/). The [runbook](runbook.md) explains retry limits, restart recovery and ambiguous-write holds.

The reviewer page's workflow explorer uses recorded JSON from real local Engine execution with deterministic fixture providers. Its buttons inspect saved examples; they do not run live APIs. A separate Gemini API smoke sample is available for each workflow. The full local application below executes new events and persists their decisions.

## Run it without service accounts or API keys

Requires Python 3.11–3.13, Git and internet access to install dependencies.

```bash
git clone https://github.com/aaditya599fx/commerceops-ai.git
cd commerceops-ai
./scripts/start.sh
```

Open http://localhost:8000 and copy APP_TOKEN from the locally generated .env into the access form. Keep APP_MODE=fixture. This is a local access password; no Gemini, OpenAI, Shopify, Slack, HubSpot or Google account is needed for fixture mode.

Try Eligible cart, inspect its draft and approve it. Receipts are explicitly labelled fixture:. Replay the event, then run No-consent case and the five other workflow buttons. A product ends as draft_ready; operational workflows end as completed. The cart waits for a decision first. Fixture approval is not evidence of a real Slack human click; the separate live record supplies that evidence.

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/verify_exports.py
.venv/bin/python scripts/build_review_bundle.py
```

The last command executes all six workflows in an isolated temporary fixture database, checks a policy block and duplicate receipt preservation, and builds an offline review page at runtime/reviewer-site. Serve it using Python's http.server if desired. It does not call live service APIs. The separate full workload is reproducible with scripts/evaluate.py; its 161-event result is a deterministic fixture evaluation.

The other three exports provide the durable queue dispatcher, Shopify checkout poll and daily brief schedule. Exports are actual n8n CLI output; import candidates generated by build_workflows.py are separate. Local verification used n8n 2.4.4.

## What the evidence establishes

- The eligible imported synthetic cart completed through real n8n, Gemini, a signed authorized human Slack decision, HubSpot and Google Sheets. Independent reads each found exactly one matching task/row after duplicate replay. The no-consent sample produced no generation or effects.
- The approved Shopify product generated a genuine signed products/create webhook, accepted with 200 OK on attempt 1. n8n/Gemini produced a local draft. API readback confirmed DRAFT, publishedAt null, price 0 and quantity 0. It created no Slack, HubSpot or Sheets effects.
- All six workflow processors passed the recorded small real-Gemini schema/policy smoke sample, without dispatching external actions. That sample does not measure classification quality.
- The 161-event deterministic evaluation completed 152 eligible events, blocked 9 and suppressed 30 duplicate deliveries with zero duplicate recorded effect keys. Fixture schema pass counts do not measure real model quality.
- 65 behavioral/failure tests passed with GitHub CI. Tests include authentication, consent changes, output/schema rejection, outages/rate limits, restart recovery, signing rotation and partial callback renewal.

## Tradeoffs worth asking about

The worker has a single-process lock rather than distributed leases. Live writes with uncertain outcomes are held for reconciliation; exactly-once delivery at third parties is not guaranteed. Product content is intentionally extractive to enforce factual grounding. The model explains customer segments and stock calculations instead of deciding them. Actual order-created/updated delivery and recovery of a real abandoned checkout were not exercised. Docker/PostgreSQL options are supplied but untested on this host. Permanent backend hosting, multi-tenant isolation and broader live-commerce validation remain future work.

Earlier provider failures, failed Shopify deliveries and two expired tunnels are documented in [live-verification.md](live-verification.md). No revenue lift, time saving, accuracy improvement or production reliability is claimed.
